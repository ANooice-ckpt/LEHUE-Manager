# 冻结前 P0 修复与升级

本轮保留实验已验证的 **20 小时、10 秒、7200 条**基准和 **6480 条有效样本**门槛，不调整科研纳入标准。

## 被试每日操作

1. 次晨连接设备，先将前一天完整原始数据保存到手机，确认保存成功。
2. 开启当天记录并断开蓝牙，按教学要求佩戴。首日无旧文件时直接开始；最终日次晨保存后不再开启新记录。
3. 上传刚保存的文件并填写晨间问卷。上传失败保留原文件、稍后重试，不需要等网络恢复才开始新记录。
4. 睡前填写睡前问卷并按教学要求放置、充电，不提前保存或结束记录。

所有正式日使用同一流程。准备教学练习短录、断连、重连、保存、上传、再次启动；主试优先查看第一个完整日的已有 QC，异常者再单独协助。系统不新增每日操作确认表。实际设备充电、放置和保存步骤以已验证的教学操作为准。

## 七项修复

| P0 | 行为 |
|---|---|
| 问卷收尾 | 明确任务日期不再被最终日覆盖；保留晚问卷补填；最终晨间问卷到次日开放；仅旧表首次增加日历列时迁移旧晨间日期 |
| GPS 补传 | OwnTracks / Traccar 在收尾阶段接受 start_date 至结束边界内的历史位置；之后的位置确认但不保存；完成结题后停止认证 |
| Lighting 归属 | 明确的 `participant_YYYYMMDD_LIGHT.ext` / `participant_YYYY-MM-DD_LIGHT.ext` 命名若冲突直接拒绝；普通设备文件名不猜身份。错日期 raw 留存但不计完成，正确补传优先；测试文件不进入正式 QC；重复直传复用既有结果；切换任务清空文件选择 |
| S0 | 序号按问卷来源 ID 限定；联系方式指向不同人或与已有事实冲突时整份导入回滚；同文件不重复，同批同一候选不重复建人；其他来源的候选不被标成旧快照 |
| 7200 与日流程 | 次晨保存、启动、上传；全天上传任务指向前一天；Admin 与 Portal 使用同一目标；保持原样本标准 |
| 环境边界 | TEST / PROD 桶名称分别声明且不得相同；PROD 使用独立密钥和角色；错误配置在启动时失败 |
| 状态恢复 | 禁止 Web 在线替换；使用停机脚本，校验来源环境和校验和，保留 rollback 后恢复 |

## 现有部署升级

### 复查追加的三项 P0

- **Lighting 跨日重复**：同一被试、同一 SHA 的正常文件只能归属一个实验日；同日同阶段重试复用已有结果。本地上传与 OSS 直传登记均在短写事务内复核，防止两个页面同时登记到不同日期。可完整解析的记录日期须从任务日开始，允许正常跨到次日；7200 / 6480 门槛不变。已 QC 且明确错日、记录起始日指向新任务日的原始文件允许在正确日补传，旧错误记录保留且不计完成；未知、pending 或正常已归属文件不能据此跨日复用。测试文件不能转为正式文件。
- **候选重复赋号**：同时核对身份库和研究库，已有绑定或两侧不一致时返回具体编号，拒绝旧页面再次赋号。无历史重复时建立非空候选 UID 唯一索引；有历史重复时保留全部记录、输出冲突清单，并以数据库约束阻止新增重复，避免阻断既有采集。历史冲突须人工核对，不自动合并身份或移动数据。
- **结束后假延期**：结束曝光或完成结题后，普通编辑不能改变开始/结束日期；备注、批次和负责人仍可编辑，且不改动设备占用、assignment 或 GPS 凭据。Admin 同步禁用日期字段并说明原因，保存时不发送已锁字段。正常延期必须在结束曝光前进行；本次不增加结束后恢复采集流程。

Lighting 解析器升为 `light-v4`。启动不会自动改写存量 raw、归属或重算旧版 QC；若已有相邻日期重复提交的可疑文件，使用既有重新 QC 入口重跑并核对。时间信息不足以判断归属的历史记录仍需人工核对，不能靠自动猜测修正。

这些修复不等于正式冻结验收。复查发现的教学/最终次晨提示、结题与进行中上传、历史补传入口、S0 跨来源与纠错、恢复回退和备份桶检查等 P1 仍待处理。原七项表格描述的是修复范围，其剩余边界以本段说明为准。

### 升级步骤

先保存当前环境 State Bundle，并按 Windows → GitHub → TEST → PROD 的既有路径发布。本轮没有自动修改运行 `.env`、数据库或云资源。

- 将旧 TEST `OSS_BUCKET` 值移到 `OSS_BUCKET_TEST`，填写独立的 `OSS_BUCKET_PROD`。旧变量不再作为运行桶来源。对象键保持原样，不需搬迁已有 TEST 对象。
- 备份桶使用 `BACKUP_OSS_BUCKET_TEST` / `BACKUP_OSS_BUCKET_PROD`，启用时两者都需声明且不同。RAM 策略只允许该环境的 Lighting 和备份桶；应用检查配置边界，不能替代云端策略检查。
- TEST 仍兼容旧 `CREDENTIAL_ENCRYPTION_KEY`、`ADMIN_TOKEN` 和 OSS 凭据，也可移到对应 `_TEST` 项。
- 新建 PROD：`bash scripts/server_setup.sh prod` 生成 `_PROD` 密钥和管理 token，配置独立 `OSS_ROLE_NAME_PROD`。PROD 不回退读取 TEST 凭据。
- 已有 PROD：保留原密钥，迁到 `CREDENTIAL_ENCRYPTION_KEY_PROD`，不能直接生成新密钥覆盖已有数据库。原未分环境变量若属于 PROD，应迁走并为 TEST 配置自己的密钥。若确实共享密钥，先用旧版本停机导出 PROD State Bundle，再配置新的 PROD 密钥，用新版本停机恢复；State Bundle 会重加密 GPS 和 Portal 凭据。保留原包与原配置，验证恢复后再处理旧副本。
- 旧版本已经进入收尾且禁用了 GPS 的被试，不自动重启凭据，避免复活人工撤销的权限；若确需补传，由主试重置并配置当前 GPS 凭据后补传，补齐后再结题。历史可疑问卷或 S0 错合并不自动猜测修正，应对照备份和原始导入表核对。
- S0 原有问卷来源默认 `default`，继续导出同一问卷时保持该值。新问卷首次输入自己的问卷编号，后续累计表沿用；不能把每次下载日期当来源 ID。若联系方式冲突，先核对原表和既有候选信息，不能靠换来源 ID 绕过。

## 恢复命令

ZIP 放在 `server/data/snapshots/`，只传文件名：

```bash
bash scripts/server_snapshot.sh test export
bash scripts/server_snapshot.sh test restore LEHUE_TEST_state_bundle_YYYYMMDD_HHMMSSZ.zip
# PROD 同样显式指定 prod；两种环境的包不能互相恢复。
bash scripts/server_snapshot.sh prod restore LEHUE_PROD_state_bundle_YYYYMMDD_HHMMSSZ.zip
```

脚本停止 API 并确认无运行容器后再恢复；所有其他直接写库脚本也必须停止。Windows 手工恢复须先关闭本地服务，再运行 `scripts/test_snapshot.py restore <zip> --api-stopped`。失败保持 API 停止，查看输出和 `data/<env>/restore_backups/` 的 rollback，排除问题后再恢复或启动。

## 与原实验文档的差异

本轮按研究负责人决定采用统一次晨保存/上传，替代原实验文档的当晚保存/上传。仓库 README、Portal 和 Admin 已同步；原 `.sdoc` 尚未改写，应在冻结实验教学材料时同步。7200 基准没有降低；夜间放置记录的科学解释继续由实验方案与本地分析负责。

## 验证范围

自动测试覆盖问卷跨日/收尾/重启、两 GPS 客户端补传与凭据重置、Lighting 归属/测试排除/正确补传/重复直传、S0 多来源冲突回滚、环境配置拒绝和 State Bundle 离线恢复。浏览器检查使用真实页面代码和模拟 API；真实 ECS RAM 权限、OSS CORS 与停机恢复仍需在 TEST 部署执行既有 smoke test 和恢复演练。

2026-09-22 追加 P0 修复后，本地完整测试为 **85 passed / 1 skipped**，其中新增 18 个用例覆盖真实 20 小时跨午夜文件、同日与跨日并行登记、错误归属后补交、两个主试重复赋号、历史重复约束迁移、收尾/结题日期锁定及正常延期。跳过项为真实 OSS 集成；OSS 服务链使用模拟存储验证。本机 Chromium 加载实际 Admin 页面和模拟 API，确认收尾/结题日期禁用、备注请求省略锁定日期、运行期延期可用，以及切换被试时输入框锁定状态正确重置。
